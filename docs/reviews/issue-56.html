Blip Journal · Issue #56

Keep the wording an answer originally used

Resuming a draft after renaming a question silently attached untouched answers to the new wording. That changed the historical label in CSV exports.

Before · the bug

Answer A under wording v1
↓
Rename A to wording v2
↓
Resume → answer B → Done
↓
A is rewritten as v2; original wording disappears

After · the fix

Load A with its saved version v1
↓
Keep the displayed definition v2 separately
↓
Answer B → Done
↓
A stays v1; explicitly editing A adopts v2

Why this works

EntryDraft now retains a saved version ID for each loaded answer. A whole-entry autosave uses those retained IDs. Only setting an answer replaces its version with the definition shown by the runner. Answer IDs and first timestamps remain stable.

Test evidence

RED · before the fix

The regression failed on saved == original and on the original label being present in the long CSV.

GREEN · after the fix

The regression and EntryDraft suite pass after the fix. The test also checks that explicitly editing A adopts its new version. The CSV assertion is scoped to the resumed entry.

Simulator-hosted model tests inspect actual stored answers and production CSV output. The prior issue report supplies the UI reproduction; this PR does not claim a repeated GUI workflow.

Needs your input

No product decision is required. Review and merge the PR when satisfied. Already rewritten historical versions are not repaired: the original version cannot always be inferred safely.

Self-contained review artifact. No external scripts, fonts, or network requests.
