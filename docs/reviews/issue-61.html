Blip Journal · Issue #61

Warn before sharing a restore safety backup

Restore recommended saving a backup of current data, but omitted the warning that the exported JSON is readable by anyone with the file. Normal Export already showed that warning.

Before · the bug

Load a backup in Restore
↓
Tap Save a backup of current data
↓
A readable JSON file reaches the share sheet
↓
No plaintext or all-surveys disclosure on this path

After · the fix

Load a backup in Restore
↓
See: Includes all surveys and dates
↓
See: Exported files are not encrypted
↓
Choose whether to share the backup

Why this works

Export and Restore now render the same ExportDisclosure component before their share actions. The JSON backup variant adds the all-surveys-and-dates disclosure. Export behavior, encryption, authentication, and restore semantics are unchanged.

Test evidence

RED · before the fix

A rendered UI test reached the loaded Restore screen and failed because the plaintext warning was absent. Earlier authentication-blocked runs were not counted as red evidence.

GREEN · after the fix

The UI regression passes for both Restore and normal JSON Export, checking both disclosures before sharing. All 106 production app tests also pass. The reusable script creates a separate temporary test app with an in-memory journal and generated backup.

The test host skips authentication and file picking only in its temporary copy. Production authentication and project configuration are unchanged. The UI test does not share a file or restore data. XCUITest is used for rendered UI; Core tests remain Swift Testing.
