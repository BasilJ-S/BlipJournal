Blip Journal · Issue #58

A second notification must open its own entry

A → B kept the same sheet alive, so the already-resolved state still showed A. Answers intended for B could be saved against A.

Before · the bug

Open live notification A
↓
Type a note; its save is debounced
↓
Tap notification B while the sheet stays open
↓
The retained runner still belongs to A

After · the fix

Notification B changes the route task ID
↓
Disable old controls and flush A's draft
↓
Resolve B and install B's draft
↓
Answers go to B; A's saved draft survives

Why this works

A presentation session owns the current draft and replaces it only after flushing. Task cancellation and generation checks reject stale handoffs. Runners and completed details have entry-based identity. Close and Done clear only their own prompt ID. The route decision now lives in Core.

Test evidence

RED · before the fix

A regression against the extracted retain-once routing behavior failed on the new prompt ID, displayed survey, saved pending text, and answer association.

GREEN · after the fix

100 app tests and 452 core tests pass. Tests cover A → B association, A's pending text, same-ID reuse, failed flush retention, late finish callbacks, and the existing route decision cases.

The red test exercises extracted presentation state, not OS banner taps. The issue report supplies the original UI reproduction. This PR does not claim a new end-to-end OS notification run. A save failure keeps the old draft and offers Retry or Keep current entry.
